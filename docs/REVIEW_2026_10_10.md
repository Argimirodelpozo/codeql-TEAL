# Review 2026-10-10 — analysis, fixes, agent integration

Against branch `rev` at `673d6d55` (16 commits ahead of `main`, hermetic suite
5,347 passed / 99 skipped, ruff clean). Four parallel reviewers (detector guard
logic, output/query contracts, the unmerged `rev` SSA/numeric work, the lift
taint engine) produced 44 findings, each with an executed repro and a control;
two fixers then re-verified and fixed the engine-level ones, and the output
layer was fixed directly. This document records the assessment, what changed,
and what is proposed next. Repro files for every finding live in the session
scratchpad (`reports/*.md`, `repros/<area>/`); the fixed ones are now benchmark
fixtures.

## 1. Assessment

**What is unusually strong.** The substrate is deeper than any published
Algorand tool: typed SSA rebuilt from raw TEAL, a lift to Puya-shaped IR that
recompiles to behaviourally identical bytecode on ~900 mainnet programs,
immutable facts (constants, aliases, ranges, byte lengths, congruences),
interprocedural taint with guard credit, authority provenance, storage-schema
and ARC-4 type recovery, and a growing set of conditional proof obligations.
Verification culture is the real asset: a 220-case labelled benchmark with a
pinned confusion matrix, mutation gates, a 231-program mainnet findings ratchet,
behavioural differentials against a private node, and a completeness envelope
(`complete` + `notifications`) that refuses to let "no findings" mean "never
analysed".

**Where it was weak before this review.**

1. *Guard credit was existential where it must be universal.* The dominant
   defect class across both engine reviews is "a check on ONE thing credited to
   ALL": a callee's `int 0; retsub` counted as a rejection for every caller
   once any caller asserted it; a bound on one tainted sub-term credited a sink
   built from two; a comparison between two attacker inputs credited as a
   check; a join's path predicates taken as an intersection in one lifecycle
   helper while the sibling helper already walked per edge. These are the same
   class the 2026-09 audits fixed in other places (join = OR, per-edge
   dominance); the fixes below apply the already-written machinery uniformly.
2. *The machine surface was uneven.* Only `detections-scan` emitted the
   versioned finding record; `detections`, `all`, `audit` and `xcontract` emitted
   detector-private dicts (22/32 detectors: `{"message": …}` only). `taint-query`
   had no completeness envelope and exited 0 on partially parsed input. Baseline
   fingerprints collided across distinct approval exits (a NEW unguarded exit
   was silently accepted by an old baseline) and churned on a one-line shift for
   four detector families. SARIF had no `partialFingerprints`, no rule help, and
   put whole-program findings on line 1.
3. *Nothing was built for an agent.* The skill file shelled out to the CLI and
   asked the model to parse prose. There was no way to ask "what is this
   contract?" in one call, no explanation of a line, no revision diff, no MCP.
4. *Two systematic false-positive sources on real compiler output*:
   `abi-method-selector` flagged every bare (`NumAppArgs == 0`) handler PuyaPy,
   PyTeal and TEALScript emit (rows on 180/231 mainnet probes), and the lifecycle
   trio flagged any hand-written router with a shared `approve:` label.

### 2.3 Lift taint engine

Fifteen findings, all reproduced, fourteen fixed and one split (fixer report:
`scratchpad/reports/fixes_lift.md`; new fixtures under
`tests/benchmark/{tainted-fund-flow,tainted-state-write,partial-tainted-fund-flow}`,
`tests/test_review_2026_10_10_lift.py`, nine tests). Guard credit is now
**coverage**: `_classify` returns which sink registers/slot keys a condition
constrains, and a sink is guarded only when every tainted leaf of its value is
covered. The lift's OUTPUT is untouched (corpus gate 773 passed, 0 refusals).

| # | Defect | Fix |
| --- | --- | --- |
| D2 | **FN** a check on ONE tainted sub-term credited a sink built from TWO (`Amount = arg0 + arg1`, `phi(arg0, arg1)`, interprocedural twin) | coverage of every tainted leaf, unioned over dominating / post-dominating / callee-transfer guards; `_entry_guards` applies the same rule per call-site argument |
| D3 | **FN** a comparison between two attacker inputs credited as a check | each operand's credit withdrawn when the OTHER operand is attacker-dependent; a sibling payment's `gtxn 0 Amount` still bounds |
| D5 / D11 | **FN** `gtxns`/`gtxnsa` keys dropped the stack txn index; **FP** `txn` vs `txna` were different slot keys | canonical slot keys `("txn", field, idx)` / `("gtxn", gidx, field, idx)`; a non-constant stack index is no key |
| D6 / D13 | **FN** `select`, `\|`, `+`, `^` walked as conjunctions | boolean-vs-value position; OR-like ops are joins (intersection of arm credit), `select` joins its two value arms; this also credits `key == "a" \|\| key == "b"` |
| D4 | **FN** a callee `len` check credited as a VALUE check through the arg's def-tree | value-only walk stops below `_VALUE_OPAQUE_OPS` everywhere |

| D10 | **FP** a post-call sender assert in the caller never guarded the callee's sink | post-dominating guards credited at the call site |

## 3. Agent integration (new)

`src/tealql/agent/` — see [AGENT_INTEGRATION.md](AGENT_INTEGRATION.md).

- **Tool registry** (`tools.py`): 13 typed tools with JSON-Schema inputs,
  validated before anything runs; path or inline-TEAL targets; program cache.
- **Contract brief** (`brief.py`, `tealql brief`): one document — version/mode,
  ABI methods with line spans, lifecycle (updatable/deletable, creator-gated,
  time-delayed), storage schema, inner transactions, forced group shape,
  attacker-reachable sinks with verdicts, findings, health, headline.
- **MCP server** (`server.py`, `tealql mcp`, `.mcp.json`): dependency-free
  JSON-RPC 2.0 over stdio, three protocol versions, `instructions` that teach the
  model the verdict-vs-reachability distinction, tool errors as `isError`
  results.
- **`tealql explain --line N`**: source window, high-level origin, ABI method,
  SSA instruction, dominating predicates, reaching sources, reachable sinks.
- **`tealql diff OLD NEW`**: findings added/removed by a line- and
  filename-insensitive identity + the bounded semantic-equivalence verdict;
  exit 1 only on NEW findings — the CI story for upgrades and PRs.
- `CLAUDE.md` for coding agents working in the repo.

## 4. Proposals — what would push the state of the art

Ordered by expected value per effort. Items 1–3 are direct continuations of
defect classes found here; 4–7 are capabilities no Algorand tool has.

1. **Universal guard credit as a library invariant.** Both engines re-derive
   "every leaf / every arm / every caller" rules in several places. Factor one
   `GuardEvidence`-producing walker with explicit *coverage* semantics (which
   tainted leaves a guard covers) and make every detector consume it; then
   mutation-test the walker, not the detectors. The `rev` branch already
   introduced `GuardEvidence`; finish the migration.
2. **State-value provenance as a taint channel.** `Receiver <- app_global_get
   "payee"` with an unguarded writer is silent today (lift F1). The authority
   analysis already knows every writer of a constant key; seed state reads whose
   writers are not authority-preserving as a `StateValue` source. This closes
   the most realistic remaining false-negative class (attacker sets, then
   drains).
3. **Classify the mainnet ratchet once, then publish it.** The ratchet pins
   counts, not truth. The `abi-method-selector` rows on 180/231 probes were a
   systematic false positive that sat pinned for months. A one-time triage into
   TP/FP/unknown per (detector, contract), stored as a manifest, turns the ratchet
   into a measured field precision — the number the README's PRECISION caveat
   says is missing.
4. **Exploit witness generation** (teEther-style, bounded). For each CONFIRMED
   sink the engine already has the source slots (`ApplicationArgs N`, group
   sibling fields) and the path predicates. Emit a *transaction template*
   (which args/accounts/siblings the attacker must control and the constraints
   they must satisfy) and hand it to TEALFuzz or a localnet runner for
   confirmation. The brief's `attack_surface` is the natural carrier.
5. **Trace partitioning by method / lifecycle action.** Precision loss at joins
   is the root of several FPs (shared `approve:` labels, Puya's shared-exit
   shape). Partition path predicates per ABI method and OnCompletion, join only
   when the partition budget is exceeded. The `method_line_ranges` attribution
   and the Puya router decoder are the inputs.
6. **Agent-side triage loop.** With the MCP tools in place, a thin
   `tealql triage` that asks a model to classify each CONFIRMED finding
   (true/false/needs-context) using `source_context` + `decompile`, records the
   verdict with the fingerprint, and feeds `--baseline`. Keep the model's output
   as *advice* in the record (never as the finding's verdict) and measure its
   agreement against the labelled benchmark before trusting it.
7. **Per-detector remediation text.** The READMEs have "what it looks for" and
   "how it works" but no "how to fix"; SARIF `help` and the agent `list_detectors`
   now carry the README, so a remediation section lands everywhere at once.
8. **Smaller items**: `detections --all` could default to `--mode auto` after a
   deprecation period; `UnvalidatedGroupSiblingViolation` and the approval-exit
   family should carry structured `field`/`exit` data (today only the lifted
   family does); publish `tree-sitter-teal` to PyPI so `tealql` itself can be.
