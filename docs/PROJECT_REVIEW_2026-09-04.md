The best next investment is to consolidate the analysis contracts: what a value means, which program it belongs to, what a guard proves, and whether an analysis completed. The project already has substantial machinery for SSA, byte precision, interprocedural flow, type recovery, and resource reasoning. Several remaining problems arise where those layers exchange information. Fixing those boundaries should improve correctness and reduce implementation size together.

This review covers source inspection, the existing CI-style test configuration, Ruff, small local checks of analysis APIs, and comparison with current primary AVM documentation. It does not establish soundness of every detector. The local checks use synthetic analysis objects or harmless input-to-log programs; they do not execute transactions against a network. Production source was not modified.

The source inventory is 174 Python files and 46,508 physical lines, approximately 30,957 nonblank code lines after excluding comments and docstrings. There are 1,269 test functions across 128 top-level test modules; parametrization produces many more test cases. The detector benchmark has 32 policies, 94 positive fixtures, and 126 negative fixtures. The 1,019 mainnet fixture files contain 231 distinct byte contents, all declaring AVM versions 2–11. The mainnet finding ratchet already deduplicates by content; other sweeps should use the same manifest.

The strongest existing choices are immutable source snapshots, the facts/derived-view separation, the Puya-free detector path, positional operand helpers, explicit unresolved values, detector confusion baselines, and pass-firing/mutation gates. Preserve these. An AST comparison found no exact function duplicates longer than ten lines after normalizing function names; most worthwhile consolidation is semantic, rather than copy-and-paste removal.

**The following issues deserve concrete changes.** Priorities refer to this analyzer's reliability, not the severity of a vulnerability in a contract.

1. **P1: detector crashes can disappear from structured completeness metadata.** In [reporting/registry.py](../src/tealql/tealtools/reporting/registry.py#L16), `_safe()` logs a detector exception and returns `[]`. The [security runner](../src/tealql/security/run.py#L35) records `degraded` only after `detect()` returns. A synthetic throwing detector therefore produced `{"detectors":{"detections/test-boom":[]},"reports":{},"notifications":[]}`. Consumers of JSON cannot distinguish this from a successful empty result. Return a structured execution status from the shared runner and preserve it through text, JSON, SARIF, and strict execution. Extend [test_detector_runner.py](../tests/test_detector_runner.py) to check the status as well as crash isolation; its current empty-list assertion permits the problem.

2. **P1: the behavioral oracle can label an untested program faithful, and compares too few effects.** [compare.py](../tests/behavioral_lift/compare.py#L42) reduces execution to approval plus logs. Different global-state updates produce identical observations. Inner transactions, local state, boxes, and scratch exported to group siblings are also outside this comparison. Separately, dryrun exceptions append a message and continue; `diverge == 0` still means `FAITHFUL` to the caller. Executing the unmodified comparison function with a synthetic failing transport yielded ten errors, zero comparisons, and the faithful condition. The same classification occurs in [sweep_probes.py](../tests/behavioral_lift/sweep_probes.py#L72). Track attempted/completed/error counts and successful executions explicitly. Compare normalized committed effects using an appropriate local execution fixture. A missing observable must mean incomplete evidence. Keep resource consumption as a separate compatibility measure, since optimization can legitimately change cost. The SDK was absent locally, so these checks executed the original function ASTs with synthetic transport/SDK objects; no live behavioral validation was performed.

3. **P1: the declared AVM target is ahead of the implemented vocabulary.** [avm.py](../src/tealql/tealtools/language/avm.py#L24) declares v13, but has no `app_params_set`, `app_box_*`, or `poseidon2` entries. Current official [opcode documentation](https://dev.algorand.co/reference/algorand-teal/opcodes/) and [go-algorand opcode definitions](https://github.com/algorand/go-algorand/blob/master/data/transactions/logic/opcodes.go) include them at v13. This is a support gap; strict construction can refuse unsupported input. Tests against pinned Puya 5.7.1 cannot reveal features missing from both models. Pin a particular consensus/langspec revision, generate the mechanical metadata, and maintain an explicit implemented/unsupported inventory per opcode, field, version, and mode. A runtime's development branch is not evidence of mainnet activation; keep supported specification, active protocol, and installed backend versions distinct.

4. **P2: taint queries lose program identity.** [TaintQuery](../src/tealql/tealtools/dataflow/taint_query.py#L143) stores `file` but constructs the coarse graph over the entire collection. Its precise result filename comes from the first assignment, instead of the selected projection. With two identical harmless logging programs, selecting `b.teal` returned `a.teal:3` and `b.teal:3` in coarse mode, and only `a.teal:3` in precise mode. In addition, [verify_sinks](../src/tealql/security/sink_verdict.py#L90) joins findings on line number alone. A synthetic finding at `a.teal:3` marked both files' sinks confirmed. Project at the query boundary and use a structured `(program, instruction, operand role)` identity for joins. Test selection, colliding line numbers, source-map lookup, and coarse/precise attribution together.

5. **P2: call summaries merge independent return positions.** [_return_summary](../src/tealql/tealtools/lift/taint.py#L273) unions sources and parameter dependencies across all return values. The invocation transfer applies that union to every output. A synthetic subroutine returning `(constant, parameter)` gave both caller results `ApplicationArgs` taint. This is a precision loss, not a demonstrated missed finding. Store dependencies per result position and propagate each output separately. [test_ir_taint.py](../tests/test_ir_taint.py#L264) already checks positional `ValueTuple` copies; extend that guarantee through calls, multiple returns, nested calls, and recursion.

6. **P2: the query sink taxonomy trails the detector.** [taint_query.py](../src/tealql/tealtools/dataflow/taint_query.py#L49) omits `app_global_del`, `app_local_del`, `box_splice`, and `box_resize`. All four are covered by [fund_flow.py](../src/tealql/tealtools/lift/fund_flow.py#L1250). Direct calls to `classify_sink` return `None` for them; the precise query also filters results through this taxonomy. Generate both views from shared effect metadata with explicit policy exclusions. Add a bidirectional inventory test, not just positive examples for the currently listed operations.

7. **P2: normalization corrupts valid source filenames.** The location regex in [findings.py](../src/tealql/security/findings.py#L22) parses `my contract.teal:7` as `contract.teal:7`, and `dir/demo[2].teal:7` as `.teal:7`. Bracketed identities can be generated by the project's own source-name collision handling. Prefer structured locations; for the legacy string form, split the numeric suffix from the right without restricting the filename alphabet. Test spaces, collision suffixes, nested paths, and platform path spellings. Scanner-provided `rel_path` masks some cases, but direct library normalization remains incorrect.

8. **P2: arithmetic remediation needs an overflow condition.** [unsafe_division_order.py](../src/tealql/security/detections/unsafe-division-order/unsafe_division_order.py#L39) recommends multiplying before dividing without proving the wider intermediate fits. For uint64 maximum `M`, `(M // 2) * 2` succeeds, while `M * 2` overflows; the constant-fold kernel confirms this. Report the rounding issue, but condition the suggested rewrite on a range proof or suitable wide arithmetic. A regression should check both the mathematical rounding difference and the runtime overflow behavior.

Three open items in the existing September 2 review remain relevant: computed Puya routers are not decomposed into lifecycle facts; arithmetic results can lack a coarse `TealType` when no range was inferred; and byte-taint versus Boolean value-flow rules disagree about selection through storage. These are existing findings, not new discoveries in this review. The [switch transfer](../src/tealql/tealtools/cfg/path_predicates.py#L680), [range seeding](../src/tealql/tealtools/analysis/_range_seed.py), and [opaque-read classification](../src/tealql/tealtools/language/avm.py#L1138) are the relevant boundaries.

**Architecture changes should remove duplicated decisions.** I would stage the following changes, with a behavioral gate after each migration.

| Change | Why it reduces complexity | Completion criterion |
| --- | --- | --- |
| Generate versioned `OpSpec` data | Arity, result kinds, field positions, effects, and version checks currently require coordinated edits. Keep custom semantic transfers explicit. | Every supported opcode has one mechanical specification and an explicit transfer/unsupported decision. |
| Introduce structured `GuardEvidence` | Authorization, value pinning, range checks, and byte validation currently use related but separate walks and booleans. | Consumers receive subject, relation, extent, path scope, trust basis, and assumptions; no detector interprets mere dependency as validation. |
| Use one result envelope | `AnalysisResult`, scan notifications, detector `degraded`, logging, and bare lists encode overlapping failure states. | All public results carry execution status and model limitations; suppression preserves them. |
| Consolidate summaries by output and effect | Production and prototype summaries repeat similar traversal; return slots and storage effects need different facts. | One summary service handles positional returns and effects; `checked_params` is replaced by predicate-specific evidence. |
| Freeze analysis inputs after construction | Pre-IR is mutable while several caches assume it is stable; invalidation keys vary between revision, object identity, and shape. | Builder/transforms own mutation; analysis caches use program identity and revision consistently. |
| Move remaining consumers to facts-at-use | Derived SSA reconstruction and annotation passes preserve two ways to ask related questions. | Migrate consumer by consumer, then delete unused compatibility paths; retain presentation views only where needed. |

The prototype's [checked_params](../src/tealql/tealtools/lift/summaries.py#L93) currently means that a parameter influences an entry-block assertion. That alone does not prove the parameter satisfies a sink's policy. It has no production consumers in `src/` today; do not promote it into a sanitizer without changing its contract.

Likewise, a storage-derived address is currently trusted based on its read shape in [_action_guards.py](../src/tealql/security/_action_guards.py#L61), while lifted sender recognition has a different trust test. Make the assumption explicit: authorization through stored data is conditional on who may write that data. The current `GUARDED` label also means a covering detector returned no matching finding, which is weaker than a recorded proof. Prefer explicit proof evidence or a more limited label.

Splitting large modules helps only when ownership becomes clearer. The largest functions include `stacksim._exec` (357 lines), `parse_nodes` (326), `_byte_taint_impl` (316), `_Lifter._build_impl` (289), and `fund_flow._classify` (245). Decompose parsing into normalization/recovery/diagnostics and guard classification into small predicate transfers. Preserve the shared stack executor: duplicating it across representations would reverse an existing architectural improvement. Static import analysis also finds cycles across analysis/SSA and lift/transforms/type recovery; lazy imports prevent some import-time failures but do not remove that conceptual coupling. Extend the existing layering tests to cover dependency contracts, including imports inside functions.

**The most promising new analyses are relational and stateful.** The following are proposals for this project, not claims that the underlying techniques are new research.

| Direction | Useful question | Existing foundation and first bounded milestone |
| --- | --- | --- |
| Authority provenance across methods | Is an address used for authorization protected through every write that can establish or replace it? | Storage-key recovery, state flows, and guard evidence. Start with constant global keys and method write summaries; report external-state assumptions explicitly. |
| Shared-box permission and effect analysis | Which apps may read/write a box, whose minimum balance changes, and do accesses satisfy the applicable permission and call-stack rules? | Resource demand and intercontract graphs, after v13 support. Start with a user-supplied closed set of apps and static owner/key identities. |
| Relational atomic-group obligations | Do accepted group layouts bind payment/asset identity, receiver, amount, and relevant fees to the operation being authorized? | Group shape, sibling checks, inner-transaction fields, and difference constraints. Prove small group templates first, with unknown for unmodeled group members. |
| Cryptographic statement binding | Does a verified signature or proof commit to the action's relevant fields and its required replay domain? | Byte intervals, ABI recovery, and value identities. Start with explicit signature/preimage annotations and exact field correspondence; cryptographic assumptions remain declared inputs. |
| Lifecycle and upgrade state machines | Does every accepted upgrade satisfy a stored proposal, a delay measured from that proposal, and the intended authorization transition? | Lifecycle exits, timestamps, state summaries. Replace timestamp-check presence with a relational obligation; first support constant proposal-state keys. |
| Rounding and conservation analysis | Which operations lose precision, who benefits from rounding, and are application-specific conservation invariants preserved? | uint64/bigint ranges, wide operations, recovered types, and fund effects. Begin with bounded linear expressions and explicit units/invariants. |
| Resource sufficiency and recoverability | Can required operations complete under the declared resources, box I/O budget, fees, opcode budget, and minimum balance? | Budget and resource-demand modules. Produce conditional requirements per method/group; maintain separate cost lower/upper bounds and explicit environmental assumptions. |
| Compatibility analysis between revisions | Does a proposed revision preserve specified ABI, storage, permission, and method-effect contracts? | ARC-4/ARC-56 recovery, source identities, and method summaries. Start with structural/schema compatibility; use proof obligations for supported semantic fragments and unknown elsewhere. |

Shared-box work has a particularly timely AVM-specific foundation. Official [box storage semantics](https://dev.algorand.co/concepts/smart-contracts/storage/box/) distinguish resource availability from permission and describe opt-in foreign reads, family writes, owner-funded minimum balance, and family call-stack restrictions. Model those protocol restrictions before reporting candidates; ordinary EVM reentrancy rules are not a substitute.

Resource analysis must also distinguish traditional foreign arrays from v12 access lists. The official [resource usage specification](https://dev.algorand.co/concepts/smart-contracts/resource-usage/#access-list-a-mutually-exclusive-alternative-to-reference-arrays) describes mutually exclusive representations and explicit compound resources. The current [resource-demand document](RESOURCE_DEMAND.md) correctly treats its certificate as an optimization hint requiring independent semantic closure. Extend that contract rather than treating `complete` as a proof of sufficient transaction resources.

For scalability, apply precision selectively. Partition predicates by method, lifecycle action, creation status, and selected group role, with explicit joins when the partition budget is exceeded. This is an application of established [trace partitioning](https://www.di.ens.fr/~mauborgn/publi/toplas29.html). For finite distributive taint facts, consider matched call/return summaries or [IFDS-style realizable paths](https://research.cs.wisc.edu/wpis/papers/popl95.pdf); do not assume numeric relations and every sanitizer fit that framework. Persistent-state invariants across unbounded calls have precedent in [abstract interpretation of Michelson](https://arxiv.org/abs/2210.05217). Selected obligations could be discharged through an external Horn-clause or SMT verifier, extending the existing certificate handoff instead of embedding another execution engine. Timeouts must remain unknown and the verifier's semantics should be independently validated.

**Testing should target lost information and independent observations.** Keep the existing tests, but prioritize these additions over a general increase in snapshots or line coverage:

- Turn each issue above into a small regression at the owning boundary, with an end-to-end case where appropriate. Especially test program identity, complete/incomplete results, positional call outputs, and sink inventory parity.
- Extend existing property tests from transfer kernels to complete small CFGs: joins, loop convergence, scratch/frame flow, call returns, and fact queries before/after guards. Kernel membership alone does not test scheduling or propagation.
- Add independent reference observations. [test_range_soundness.py](../tests/test_range_soundness.py) uses this project's constant folder as its concrete oracle; that is useful internal agreement, but shared mistakes can survive. Check bounded arithmetic against mathematical semantics and a pinned AVM implementation offline where practical.
- Repair and test the behavioral harness before increasing its corpus. Require completed comparisons, successful executions for effectful paths, effect equality, and explicit inconclusive outcomes. Add a scheduled localnet job with declared dependencies and a pinned protocol, separate from fast hermetic CI.
- Audit completion accounting in corpus gates too. [test_the_whole_corpus_parses_clean](../tests/test_unknown_field_recovery.py#L507) and the call-result/shared-tail census in [test_frame_local_flow.py](../tests/test_frame_local_flow.py#L335) catch loading exceptions and continue. These individual gates can improve their error totals when construction stops succeeding. With their loaders mocked to raise on every call, all three original test functions returned successfully: 1,671 failed loads in the parser check and 231 each in the two frame checks. Record expected failures by program identity, fail on unexpected load errors, and assert the completed manifest. The mainnet detector digest already records load/detector failures explicitly; reuse that approach.
- Create compiler/idiom coverage dimensions: legacy subroutines versus `proto`, calls versus inlining, switch/match routers, scratch versus frame values, Boolean encodings, and AVM versions. Expand the existing mutation gates along these dimensions; use expected locations and evidence as well as confusion counts.
- Keep a separately reviewed holdout set grouped by code/template family. Perfect performance on 220 curated examples measures those examples. The published precision document already says this correctly. Report results per family/version and track unique successful behaviors, not only file count.
- Add a core-only CI job. Several Puya-free pre-IR tests remain gated on `importorskip("puya")`, including [test_pre_ir_operands.py](../tests/test_pre_ir_operands.py#L19) and [test_summaries.py](../tests/test_summaries.py#L14). Move the gates to actual backend tests and verify the full core analysis surface without the optional dependency.
- Measure worklist visits, fact/CFG rebuild counts, and memory retention in addition to elapsed time. Protect known complexity boundaries directly. Consolidate duplicate corpus enumeration and bound process-wide literal caches where measurements show retention matters.
- Shard the remaining aggregate corpus tests by fixture, following [test_mainnet_ratchet.py](../tests/test_mainnet_ratchet.py#L109). All four failures in this review's instrumented run were whole-corpus loops exceeding the 300-second per-test ceiling. Per-program results make timeouts attributable and distributable. Preserve aggregate ratchets through an explicit result manifest, and pin failure identities rather than only a total ceiling.

A practical implementation order is: (1) result completeness and oracle reliability; (2) program identity, sink inventory, positional summaries, and safe diagnostics; (3) versioned AVM metadata plus the known router/type gaps; (4) shared guard/effect facts; (5) authority provenance and shared-box analysis. Each change should remove an old decision path once its replacement is validated. That provides a measurable route to smaller code without setting an arbitrary line-count reduction target.
