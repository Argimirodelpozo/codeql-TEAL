# Static-analyzer audit — 2026-08-07

Scope: source ingestion and normalization, CFG/SSA construction, shared passes,
boolean and byte-granular taint, lifted-IR fund-flow guards, detector tests,
cross-file behavior, CLI behavior, and compatibility-sensitive public entry
points. This is a code audit, not a claim that every possible TEAL semantic has
been formally verified.

## Fixes implemented on `codex/static-analyzer-audit-20260807`

### Fail-closed source ingestion

- Directory validation was recursive while graph loading was top-level-only. A
  target containing only `nested/program.teal` therefore passed validation and
  produced an empty program and a false clean result. Loading is now recursive.
- Nested filesystem paths are retained relative to the target root, preventing
  two `*/prog.teal` contracts from colliding. In-memory mappings preserve their
  historical basename when unique and expand only colliding names; `SSAProgram({})`
  remains a supported empty-program API.
- Existing non-TEAL files and empty filesystem directories now fail explicitly
  instead of looking like analyzed empty programs.

### Cross-program isolation

- Stable input propagation was keyed only by opcode/immediates. In a directory
  program, reads in file B could be rewired to file A's Creator/Sender/input
  variable. The source file is now part of every canonical-input key.

### Parser normalization

- Inline-comment quote tracking treated every quote preceded by `\\` as escaped.
  With an even run of backslashes, a valid closing quote was missed and a later
  quote-bearing comment could pollute the literal or make strict parsing reject
  the file. Escaping now uses odd/even backslash parity.

### Taint soundness

- `CallerApplicationID` and `CallerApplicationAddress` are no longer trusted
  byte-validation pins. They identify the immediate caller, but an attacker can
  deploy that caller application.
- Generic taint now propagates through length/bit-length, comparisons, boolean
  operators, `bzero`, and a tainted `select` condition. Each result is controlled
  by the tainted operand even when it contains no source bytes verbatim.
- Polymorphic byte `setbit` now preserves the base value's byte-taint channel and
  taints the possibly written byte when the bit or index is controlled. Byte
  length propagation recognizes `setbit` as length-preserving.
- A controlled `setbyte` destination now taints the possible output window even
  when the byte being written is a clean constant.

### Guard-classification soundness

- SSA fund-flow fallback no longer credits length-only checks, bypassable `||`
  arms, exclusions, self-comparisons, or `x % 1` tautologies as value guards.
  Lifted-IR guard classification gained the matching self/modulo checks and
  treats `bzero` as value-opaque.
- Sender authentication now requires exactly one current-transaction Sender and
  one trustworthy, address-shaped identity. `Sender == ApplicationArgs[n]`,
  `Sender == gtxn n Sender`, short constants, `Sender == Sender`, and comparisons
  involving Creator without Sender no longer suppress findings. Negated forms
  that semantically require equality are still recognized.
- The existing `sender_creator_vars()` result is preserved for downstream API
  compatibility; internal guard consumers use the narrower new `sender_vars()`.

### Analysis purity and metadata tests

- Validation-enabled byte taint temporarily unifies stack/input variables. It
  restored forward inputs and flags but leaked rewritten reverse `.uses` links,
  making subsequent analyses order-dependent. Reverse def-use state is now
  snapshotted and restored too.
- The VRF multi-output test expected the old `uint64` verification flag after
  shared AVM metadata had intentionally refined all verification/existence flags
  to `bool`. The stale test now asserts the current public metadata contract.

## Validation

- Detector benchmark: 93 TP, 0 FP, 0 FN, 129 TN.
- Focused regression groups cover source loading, CLI recursion, input
  propagation, boolean/byte taint, fund-flow guards, parser normalization,
  cross-contract fund flow, and lift representation.
- `python -m compileall` and `git diff --check` pass.
- The pre-change full baseline had 3,189 passes, 10 skips, and one stale VRF
  expectation failure; the expectation is fixed in this branch.
- Final post-change suite: **3,221 passed, 10 skipped** (`pytest -q -n 4`).

## Recommended next work

### P0 — semantic foundations

1. **Field-aware guard semantics.** A bounded Amount check can be a useful
   validation, while `Receiver < constant` or `Receiver != ZeroAddress` does not
   authorize a payee. Today the common guard classifier is mostly value-centric.
   Add a policy keyed by sink field: identity fields require equality to a
   trusted/allowlisted identity; numeric value fields may accept proven ranges.

2. **Predicate simplification / bounded SMT.** The targeted tautology fixes cover
   observed cases, not the algebraic family (`x & 0 == 0`, equivalent expressions,
   infeasible paths). Build a pure expression normalizer first, then optionally a
   bounded solver over uint64/bytes expressions. Solver answers must be used only
   when proven; timeout/unknown stays conservative.

3. **One interprocedural taint substrate.** Boolean SSA taint, byte intervals,
   pre-IR taint, scratch/frame bridges, and cross-contract propagation currently
   encode overlapping flow rules. Move toward IFDS/IDE-style summaries with
   selectable facts (source slot, byte interval, scalar influence). Keep the
   existing APIs as projections during migration and differential-test old vs new.

4. **Mutation versioning for cached analyses.** Several analyses cache results on
   mutable `SSAProgram` objects. Introduce a program revision counter incremented
   by every mutating pass and include it in cache keys, or make the analysis input
   immutable. This removes an entire class of order-dependent stale results.

### P1 — ingestion and specification drift

5. **Strict Algorand address decoding.** The `addr` normalizer currently accepts
   any base32 payload decoding to at least 32 bytes and truncates it; it does not
   enforce exact encoded length or checksum. Add a strict mode backed by the
   canonical checksum algorithm, diagnostics, and compatibility tests before
   making it the default (some existing synthetic fixtures use noncanonical
   address spellings).

6. **Source identity as a first-class type.** File strings currently serve as
   display names, graph identity, config-glob keys, and cache scope. Introduce a
   `SourceId(root, relative_path)` internally with a stable `.file` string adapter
   so nested sources, in-memory buffers, and downstream integrations cannot
   accidentally collide.

7. **AVM differential CI.** Keep the hermetic langspec/Puya drift tests, and add a
   scheduled job that assembles generated literal/opcode programs against an
   Algorand node/toolchain. Fail on stack arity, field type, opcode version, or
   pseudo-op decoding drift; update the pinned spec deliberately.

### New analysis passes/detectors

8. **Attacker-controlled resource exhaustion.** Combine taint, range, loop-cost,
   and opcode-budget analysis to report attacker-controlled iteration counts,
   byte-operation sizes, or branch choices that can exhaust budget and deny a
   valid action. Emit a cost witness and the controlling input.

9. **Box/state minimum-balance growth.** Track box create/resize/splice and state
   growth against attacker-controlled names/sizes and required funding. Report
   unbounded or repeatable minimum-balance consumption separately from arbitrary
   key writes.

10. **Cross-contract caller capability checks.** Model constant/allowlisted
    application callers explicitly. `CallerApplication*` is attacker-influenceable
    by default; it becomes authorization only when compared to a trusted app ID or
    address. Propagate that fact through multi-hop call summaries.

11. **Lifecycle/state-machine consistency.** Summarize which guards hold for each
    OnCompletion/ABI action and compare update, delete, opt-in, close-out, and
    clear-state transitions. Look for an action that bypasses invariants enforced
    by its siblings rather than merely checking each action in isolation.

### Test and performance program

12. Expand the benchmark with adversarial identities, infeasible/vacuous guards,
    nested multi-file projects, and real contracts sampled independently of the
    detector authors. Preserve the current curated corpus as the regression spec;
    report field metrics separately.
13. Add a generic invariant test for every analysis advertised as read-only:
    serialize assignments, phi args, reverse uses, flags, and caches before/after.
14. Profile a representative directory scan and batch shared fixpoints by program
    revision. Path predicates, ranges, frame/scratch summaries, and the lift should
    each be computed once per revision, independent of detector count.
